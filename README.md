# AI Challenge W5

Standalone-чат с агентом, профилями пользователей и автоматической трёхслойной
моделью памяти. Приложение хранит независимые чат-сессии, персональные настройки,
данные текущей задачи и знания каждого профиля в разных областях памяти.

Агент изолирован от кода на уровне архитектуры: ему передаются системная
инструкция, контекст оркестрации, память и снимок состояния задачи. У провайдера нет tools/function
calling, доступа к файлам, репозиторию, shell или окружению процесса.

## Что внутри

- FastAPI backend и минималистичный chat-first интерфейс;
- память, процесс задачи и мобильная навигация открываются по запросу;
- автомат задач `planning → awaiting_approval → execution → validation → done`
  со строгими переходами, паузой и продолжением;
- редактируемые инварианты ответов: эмодзи, верхний регистр и лимит предложений;
- неявное создание профиля через короткое интервью с агентом;
- локальные профили с языком, тоном, подробностью, форматом и ограничениями;
- отдельные чат-сессии с независимой краткосрочной памятью;
- рабочая память для цели, ограничений и решений текущей задачи;
- долговременная память для сведений о пользователе, предпочтений и общих знаний;
- автоматическое извлечение важных фактов и ручные slash-команды;
- исправление рабочей памяти с заменой значений и ссылками на исходные сообщения;
- повтор последнего незавершённого ответа после ошибки или перезапуска;
- SQLite-хранилище всех слоёв, переживающее перезапуск;
- input/output policy для ограничения пользовательского ввода и ответа;
- изолированный DeepSeek provider;
- тесты backend, provider и frontend syntax check в CI.

Benchmark, runtime debug-настройки, multi-agent логика, workflow-интеграции и
инструменты работы с кодом в проект не входят.

## Запуск

Требуется Python 3.11+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
cp .env.example .env
```

Заполните `DEEPSEEK_API_KEY` в `.env`, затем запустите сервер:

```bash
set -a
source .env
set +a
uvicorn app.main:app --reload --port 8000
```

Откройте <http://127.0.0.1:8000>. История по умолчанию хранится в
`data/chat.sqlite3`; путь можно изменить через `CHAT_DB_PATH`.

## API

- `GET /api/health` — состояние backend и наличие ключа DeepSeek;
- `GET /api/invariants` — общие правила ответов;
- `PUT /api/invariants` — сохранить правила с актуальной `revision`;
- `GET /api/profiles` — список профилей;
- `POST /api/profiles/auto` — создать пустой автопрофиль для интервью;
- `POST /api/profiles` — создать уже заполненный профиль через API;
- `PUT /api/profiles/{id}` — вручную скорректировать профиль;
- `DELETE /api/profiles/{id}` — удалить профиль вместе с его чатами и памятью;
- `POST /api/chat/sessions` с `profile_id` — создать чат профиля;
- `GET /api/chat/sessions?profile_id={id}` — список чатов профиля;
- `DELETE /api/chat/sessions?profile_id={id}` — удалить чаты профиля;
- `GET /api/chat/sessions/{id}` — получить историю чата;
- `POST /api/chat/sessions/{id}/messages` — отправить сообщение агенту;
- `POST /api/chat/sessions/{id}/task` — создать задачу;
- `POST /api/chat/sessions/{id}/task/actions` — выполнить действие с `action` и `revision`;
- `GET /api/memory?session_id={id}` — получить working и long-term memory;
- `POST /api/memory` — вручную сохранить запись в выбранный слой;
- `DELETE /api/memory/{layer}/{id}` — удалить отдельную запись.

```text
HTTP API → ChatSessionService → ProfileOnboarding / TaskOrchestrator
                    │                       │
                    │       OrchestrationContext + MemoryContext + TaskContext
                    │                       ↓
                    │               Agent → PromptBuilder → DeepSeek API
                    ├──→ MemoryRuntime → MemoryExtractor → MemoryRepository
                    └──→ ChatSessionRepository → SQLite
```

## Разделение кода

- `app/orchestration/` — контекст оркестрации с активным профилем,
  управление интервью и этапами задачи, сборка prompt;
- `app/memory/` — сообщения диалога, отдельный `MemoryContext` для working и
  long-term memory, извлечение, дедупликация, API и хранилище памяти;
- `app/state/` — состояния интервью и задачи, результаты шагов и правила переходов;
- `app/storage/` — SQLite-хранилище чат-сессий, атомарная запись сообщений и
  состояния задачи, блокировки и проверка версий;
- `app/services/chat_sessions.py` — координация этих частей и адаптация к HTTP-моделям;
- `app/agents/` — вызов модели, политики ввода/вывода и схемы результатов этапов.

Профиль передаётся через `OrchestrationContext.profile`. Записи памяти
передаются отдельно через `MemoryContext`; история диалога остаётся отдельной
последовательностью сообщений. `TaskContext` содержит только состояние и
материалы задачи: профиль и память не записываются в него. Для каждого запроса
сервис заново загружает профиль и память, поэтому редактирование профиля не
меняет прогресс задачи или сохранённые воспоминания.

Прежние импорты из `app/services/profiles.py`, `app/services/memory.py` и
агентских модулей интервью, извлечения и состояний сохранены как адаптеры.
API задач включает состояние ожидания утверждения,
явными действиями и структурированными ошибками переходов. Состояние интервью представлено
отдельным `OnboardingState`, а его сохранение использует существующие столбцы
профиля без миграции данных.

## Инварианты ответов

Пункт **Инварианты** в боковом меню управляет тремя общими правилами для всех
профилей: минимум эмодзи, только заглавные буквы и максимум предложений.
По умолчанию включены все три, лимиты — 3 эмодзи и 3 предложения. Правила можно
отключать и менять лимиты от 1 до 10; пример формата обновляется в меню.
Активные ограничения видны под названием чата.

Правила хранятся отдельно от диалога, профиля и памяти. При конфликте ассистент
объясняет отказ и называет правило. Отказ тоже соблюдает формат, не меняет
прогресс задачи и не запускает извлечение памяти. Длинный ответ не обрезается
молча. Настройки переживают перезапуск и очистку чатов; новая редакция действует
на новые запросы.

Описание реализации и правила подсчёта: [инварианты](docs/invariants.md).

## Персонализация

Каждый чат привязан к одному профилю. Новый профиль сначала пустой: пользователь
сразу пишет реальную задачу, сервис сохраняет её и запускает интервью из трёх
коротких шагов:

1. имя, роль и уровень опыта;
2. желаемая подробность и формат;
3. тон и дополнительные ограничения.

`ProfileInterviewer` отдельным вызовом модели превращает свободные ответы в
валидированный JSON и постепенно обновляет профиль. Состояние (`0…3`,
`onboarding_complete`) хранится в SQLite и переживает перезапуск. Когда интервью
закончено, агент автоматически возвращается к первой задаче и отвечает уже с
новым профилем. Интервью можно пропустить сообщением `/skip`.

Перед каждым рабочим запросом
`ChatSessionService` загружает его настройки и передаёт `PromptBuilder`, который
добавляет отдельную секцию `USER_PROFILE` в system prompt. Профиль управляет
языком, тоном, подробностью и форматом ответа, но не может отменять системную
политику или текущий запрос пользователя.

Доступные настройки:

- `language` — язык ответа;
- `tone` — `neutral`, `friendly`, `formal` или `technical`;
- `detail_level` — `brief`, `balanced` или `detailed`;
- `response_format` — `plain`, `bullets` или `steps`;
- `constraints` — до десяти пользовательских ограничений.

Кнопка «Новый пользователь» создаёт только пустую запись — содержимое профиля
формирует агент в диалоге. Шестерёнка нужна для прозрачности, необязательной
ручной коррекции и удаления профиля вместе с его чатами и памятью. Защищённый
профиль «Основной» удалить нельзя. Старые базы автоматически получают его:
существующие чаты и долговременные воспоминания мигрируют в него без потери
данных.

## Модель памяти

| Слой | Содержимое | Scope | Запись |
|---|---|---|---|
| Short-term | сообщения диалога | текущая чат-сессия | автоматически при отправке |
| Working | цель, план, ограничения, решения задачи | текущая чат-сессия | автоматически или через slash-команду/API |
| Long-term | сведения о пользователе, предпочтения, устойчивые знания | все чаты одного профиля | автоматически или через slash-команду/API |

Слои физически разделены в SQLite: `chat_messages`, `working_memory` и
`long_term_memory`. Удаление чатов удаляет short-term и связанную working memory,
но не затрагивает long-term memory.

Перед запросом `PromptBuilder` собирает системную инструкцию, профиль из контекста оркестрации,
долговременную память этого профиля, рабочую память текущей задачи, ограниченное
окно диалога и новый вопрос.
Записи памяти передаются модели как недоверенные данные, а не как инструкции.
Каждый явный слой ограничен последними 30 записями и 12 000 символов.

Перед ответом отдельный интерпретатор разбирает явно сообщённые пользователем
цели, ограничения, решения, определения терминов и уточнения. Исправление
заменяет прежнее значение; новая цель очищает рабочую память предыдущей задачи.
Неясная отмена вызывает уточняющий вопрос без изменения памяти. Агент получает
предварительный снимок, а новые записи сохраняются атомарно вместе с ответом.

После ответа extraction-запрос сохраняет сведения о пользователе, предпочтения
и устойчивые знания в long-term. Обычные вопросы, догадки модели, секреты и
точные дубликаты не сохраняются. Если интерпретация или extraction недоступны,
чат отвечает с уже сохранённой памятью. У записей, созданных из диалога или
slash-команд, есть ссылка на исходное сообщение.

При ошибке генерации пользовательское сообщение остаётся в истории с кнопкой
«Повторить ответ». Повтор использует сохранённый разбор памяти и не создаёт
дубликат сообщения. Незавершённый ход переживает перезапуск; очередь сообщений
ждёт успешного повтора и остаётся привязанной к исходному чату. Подробнее:
[память и восстановление](docs/chat-memory.md).

Для ручного контроля в поле сообщения по-прежнему доступен autocomplete
slash-команд:

- working memory: `/goal`, `/constraint`, `/decision`;
- long-term memory: `/profile`, `/preference`, `/knowledge`.

Например, `/goal Подготовить демонстрацию` сохраняет цель только для текущего
чата, а `/preference Отвечать кратко` действует во всех чатах активного профиля.
Команды сохраняются через memory API, отображаются в истории отдельными
карточками и не отправляются языковой модели как сообщения диалога.

Пока агент отвечает, поле ввода остаётся доступным. Новые сообщения попадают в
видимую follow-up очередь, из которой их можно удалить; после завершения ответа
они отправляются последовательно. В чате в это время показывается анимированный
индикатор ответа. Если модель завершила генерацию по лимиту токенов, provider
автоматически запрашивает продолжение и склеивает полный ответ.

Пример создания пустого автопрофиля:

```bash
curl -X POST http://127.0.0.1:8000/api/profiles/auto
```

## Задачи

Введите цель и требования в поле сообщения и нажмите **Создать задачу**.
Для нового пользователя сначала завершите интервью профиля в обычной переписке
или отправьте `/skip`. Кнопка создания задачи доступна после завершения интервью.
Сформируйте и утвердите план, затем выполняйте шаги кнопкой под историей чата.
После формирования задача находится в `awaiting_approval`: выполнение недоступно
до явного утверждения пользователем. Пересмотр плана требует нового утверждения.
Каждое нажатие выполняет одно действие; после последнего шага доступна проверка.
Замечания проверки добавляют шаги исправления, успешная проверка завершает задачу.

Схема над чатом показывает текущий этап, а вкладка **Процесс** справа — цепочку
шагов, критерии и сохранённые результаты. Во время запроса в истории появляется
карточка выполняемого действия с анимацией и временем ожидания. Вкладка **Память**
остаётся доступна; план и управление не перекрывают сообщения.

**Пауза** сохраняет этап, прогресс и ожидаемое действие. Если ответ уже
генерируется, он завершится и сохранится. **Продолжить** снимает паузу, после
чего выполняется сохранённое ожидаемое действие отдельным нажатием. Во время
задачи изменения требований вносятся через **Пересмотреть план**. Готовые
результаты предыдущего плана остаются доступны агенту.

В одном чате хранится одна задача. Для следующей задачи создайте новый чат.
Обычная переписка доступна в чатах без задачи и после завершения задачи.
SQLite автоматически получает новую таблицу `chat_tasks`; прежняя история
сохраняется. Снимок задачи передаётся модели отдельно от обрезаемой истории.
На каждом этапе агент также получает активный профиль и память этого пользователя.
Задачи принадлежат чатам профиля и изолированы при переключении пользователей.

Для локального запуска используйте один процесс Uvicorn. В нём параллельное
выполнение одного шага блокируется. Проверка версий в SQLite защищает сохранение
и между процессами, но несколько workers могут одновременно вызвать модель
для одного шага. Пауза действует на границах действий и не отменяет запрос
к провайдеру. При аварийном завершении процесса незавершённое действие можно
повторить из последнего сохранённого снимка.

Строгие переходы и API отказов: [контролируемые переходы](docs/controlled-transitions.md).
