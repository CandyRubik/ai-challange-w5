# День 28 Локальная LLM и RAG

RAG-чат работает с локальной Qwen, локальным индексом книги и локальными
моделями поиска. Живой прогон с запрещёнными внешними соединениями backend
прошёл ответы по книге, сохранение и исправление памяти, отказ для темы вне
индекса и продолжение после перезапуска. В сравнении на одинаковых фрагментах
DeepSeek отвечала быстрее и немного полнее; Qwen работала без облачного ключа.

## Локальный путь ответа

Вопрос → Qwen формирует самостоятельный поисковый запрос → multilingual E5
вычисляет embedding → FAISS выбирает кандидатов → локальный cross-encoder
отбирает фрагменты → Qwen возвращает тезисы с ID цитат → сервер проверяет
источники и подставляет дословные цитаты из локального индекса.

Использован готовый индекс W4: sample главы 6 Java Concurrency in Practice,
22 страницы, 65 структурных чанков. Сохранилась и альтернативная стратегия
из 49 фиксированных чанков. Модель embeddings — `intfloat/multilingual-e5-small`,
reranker — `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`. Скрипт подготовки копирует
реальные веса snapshot, индекс и PDF в W5; пути к исходному проекту во время
работы не нужны. Контрольные суммы и revisions находятся в
[отчёте](day28-artifacts/evaluation.json).

Локальные загрузчики используют `local_files_only=True`, без скачивания при
ошибке. PDF открывается через локальный endpoint. Облачный вариант выбирается
явно; автоматического перехода в облако нет. Провайдер и имя модели хода
записываются до генерации и сохраняются при повторе после перезапуска.

JSON Schema ограничивает структуру ответа Qwen. Вместо переписывания английского
текста PDF модель выбирает ID готовых цитат; сервер разрешает их только в
переданные фрагменты. Это устраняет ошибки копирования переносов и пунктуации.
Точное совпадение цитаты подтверждает происхождение текста, но смысловую связь
между цитатой и тезисом оценивает отдельная проверка сохранённых ответов.

## Сравнение моделей

[Набор вопросов](../evaluation/day28-questions.json) содержит 7 содержательных
и 3 отрицательных случая из дня 24. Для каждого вопроса локальный путь один
раз готовит контекст; обе модели получают одинаковые выдержки и вопрос, без
истории и памяти. Затем выполняются три повтора с чередованием порядка моделей.
Полный [JSON](day28-artifacts/evaluation.json) хранит контекст, его SHA-256,
ответы, цитаты, времена, параметры окружения и метрики Ollama.

Сравниваются `qwen3.5:9b-q4_K_M` и `deepseek-v4-flash`, с отключённым thinking.
Qwen получает нативную JSON Schema, DeepSeek — эквивалентную схему в prompt и
JSON mode. Для Qwen структурированные вызовы используют temperature 0;
DeepSeek использует настройку API по умолчанию. Повторяемость текста относится
к этим конфигурациям приложения, а не только к архитектуре моделей.

| Показатель | Qwen локально | DeepSeek |
|---|---:|---:|
| Генерации содержательных ответов | 21 | 21 |
| Медиана времени генерации | 5.61 с | 1.67 с |
| p95 времени генерации | 10.08 с | 2.18 с |
| Ошибки провайдера | 0 | 0 |
| Отказы проверки структуры и цитат | 0 | 0 |
| Валидные ответы с первой попытки | 21/21 | 21/21 |
| Полные по заранее записанным ожидаемым фактам | 18/21 | 20/21 |
| Повторяемость статуса на 10 вопросах | 10/10 | 10/10 |

Медиана прогретого retrieval — **0.32 с**, локальной интерпретации
в этом зафиксированном прогоне — **3.08 с**. Первый поиск в новом
процессе с загрузкой E5 и reranker занял **4.56 с**.
Время генерации в таблице включает формирование JSON и проверку цитат, но не
подготовку поискового запроса и retrieval. В интерфейсе показано полное время
хода вместе со всеми этапами. `load_duration`, `eval_count` и `eval_duration`
сохранены из [API Ollama](https://docs.ollama.com/api/chat).


Отдельный [замер запуска Qwen](day28-artifacts/cold-start.json) после выгрузки
её весов через `keep_alive=0` дал **6.04 с** для первой
генерации и **2.15 с** для следующей на том же контексте.
Загрузка весов заняла **1.74 с**. Это одна пара наблюдений на вопросе о
потокобезопасности, без retrieval и интерпретации; второй вызов также использует
прогретый кэш prompt. Повтор: `python scripts/measure_rag_cold_start.py`.

Во всех трёх отрицательных случаях фрагменты не были отобраны. Девять отказов
на вариант сформировал сам RAG, без вызова генератора; они исключены из
статистики скорости генерации и не доказывают качество отказов самой LLM.
Автоматическая проверка формата и нужного раздела прошла 30/30 у обеих
конфигураций. Она не измеряет фактическую полноту.

[Смысловая оценка Codex](day28-artifacts/quality-review.json) проверяет
сохранённые ответы всех повторов по ожидаемым фактам и их цитатам. Основные
факты верны в 21/21 генерации обеих моделей. Qwen во всех повторах вопроса
про FutureRenderer пропускает ожидание `Future.get`; DeepSeek пропускает этот
факт в одном из трёх повторов. У Qwen также есть более широкая формулировка
про время отрисовки страницы вместо времени загрузки изображений и неточный
перевод `handle` как «обработчик». DeepSeek чаще добавляет подробности.

Тексты Qwen совпали во всех трёх повторах каждого из семи содержательных
вопросов. У DeepSeek формулировки менялись во всех семи случаях; основной
ответ сохранялся, но полнота FutureRenderer менялась. Это небольшой
повторно используемый набор, на котором настраивалось цитирование, а не
независимая выборка. Оценка выполнена Codex и требует проверки человеком
для выводов о качестве на произвольных вопросах. p95 здесь описывает
21 наблюдение, без статистической гарантии.

## Проверка без внешней сети

[Живой офлайн-прогон](day28-artifacts/offline-smoke.json) использовал настоящую
Qwen, E5, FAISS, reranker, SQLite и HTTP API нового экрана. У процесса отсутствует
ключ DeepSeek, внешние socket-соединения backend запрещены; локальный Ollama
остаётся доступным по loopback. [Сетевой отчёт](day28-artifacts/offline-network.json)
содержит успешную самопроверку запрета и ноль внешних попыток приложения.
Это изоляция backend, без изменения сети компьютера.

Прогон сохранил цель объяснить Executor новичку, записал ограничение «Кратко»,
заменил его на «Подробно», ответил о потокобезопасности с цитатой книги и
вернул цель со ссылкой на сообщение пользователя. StructuredTaskScope получил
отказ без цитат и без вызова генератора. PDF был получен локально.
[После перезапуска](day28-artifacts/offline-restart.json) история и память
сохранились; повторное чтение цели и отрицательный вопрос также прошли.
[Сетевой отчёт перезапуска](day28-artifacts/offline-restart-network.json)
фиксирует тот же запрет внешних соединений.

## Видео и повторение

[Видео](day28-artifacts/day28-demo.mp4) — монтаж настоящих кадров браузера:
локальный вопрос и ответ, переключение на DeepSeek, ответ облачной модели,
отказ для темы вне книги, память после перезапуска и новый ответ офлайн.
Русские подписи встроены в изображение; видео без звука. Для сборки нужны `ffmpeg` и `rsvg-convert`. Паузы генерации
сокращены. Исходные JPEG и [субтитры](day28-artifacts/day28-demo.srt) сохранены.
Видео не является непрерывной записью экрана.

Запуск и первоначальная подготовка описаны в [README](../README.md).

```bash
python scripts/prepare_local_rag.py --source ../ai-challange-w4
python scripts/run_day28_evaluation.py
python scripts/run_rag_offline.py --port 8769 --db /tmp/day28-offline.sqlite3
# В другом терминале:
python scripts/smoke_local_rag.py
python scripts/build_day28_video.py
```

Тесты покрывают сохранение источников и памяти, смену цели, уточнения,
восстановление после ошибки, миграцию W4, выбор модели во время генерации,
повтор исходной моделью после перезапуска, отказ без fallback, неизвестные
цитаты и отсутствие скачивания весов. CI также проверяет синтаксис обоих
frontend-файлов.
