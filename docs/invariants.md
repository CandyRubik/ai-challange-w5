# Инварианты ответов

В чат добавлены три заметных правила продукта: обязательные эмодзи, верхний
регистр и ограничение количества предложений. Они включены по умолчанию:
минимум 3 эмодзи, заглавные буквы, максимум 3 предложения.

## Настройки

В боковом меню есть кнопка **Инварианты** со счётчиком активных правил.
Индикаторы под названием чата показывают действующие ограничения и тоже
открывают настройки. В меню можно включить или отключить каждое правило,
изменить минимум эмодзи и максимум предложений в диапазоне 1–10. Пример формата
обновляется сразу, реальные настройки меняются кнопкой **Сохранить**.

Правила общие для всех профилей. Хранятся в отдельной таблице
`product_invariants`, переживают перезапуск и очистку чатов. Профиль, диалог,
автоматическое извлечение и ручное добавление памяти не изменяют эту таблицу.
Новая редакция применяется к новым запросам; уже начатое действие использует
снимок настроек, полученный в начале запроса.

## Применение и отказ

Перед вызовом модели правила входят в `OrchestrationContext.invariants`.
`PromptBuilder` добавляет обязательную секцию `PRODUCT_INVARIANTS`: профиль и
память не могут её переопределить. Отключение обычного контекста не отключает
инварианты. Для этапов задач правила относятся к текстовым значениям, схема
JSON сохраняется.

Прямые просьбы ответить без эмодзи, строчными буквами, заданным количеством
предложений сверх лимита или игнорировать правила получают отказ до вызова
модели. Проверка распознаёт распространённые формулировки на русском и
английском; цитаты и вопросы о правилах сами по себе не являются конфликтом.
Разнообразие естественного языка не покрывается полностью регулярными
выражениями: прочие формулировки обрабатываются моделью согласно prompt.

Каждый опубликованный ответ дополнительно проходит проверку кодом. Обычный
текст переводится в верхний регистр, недостающие эмодзи добавляются. Ответ сверх
лимита не обрезается — вместо него появляется объяснение отказа. Код в Markdown,
ссылки и адреса электронной почты, которые пришлось бы менять при переводе
в верхний регистр, также блокируются вместо скрытого повреждения.

Количество предложений определяется по `.`, `!`, `?` и `…`; десятичные точки,
номера пунктов списка и хвост из эмодзи не добавляют предложения. Это явное
правило подсчёта, а не лингвистический анализ: сокращения с точками тоже могут
увеличить счётчик. Составные эмодзи, например семья, флаг или жест с оттенком
кожи, считаются как одна последовательность.

Пример отказа:

> НЕ МОГУ ВЫПОЛНИТЬ ЗАПРОС В ТАКОМ ФОРМАТЕ: ДЕЙСТВУЮТ ПРАВИЛА «МИНИМУМ 3
> ЭМОДЗИ», «ТОЛЬКО ВЕРХНИЙ РЕГИСТР»; ИЗМЕНИТЬ ИХ МОЖНО В МЕНЮ «ИНВАРИАНТЫ» 💬 ✨ 🙂

Отказ выделяется в истории и содержит название нарушаемого правила и способ
изменить настройки. Он сам соблюдает ограничения, в том числе лимит в одно
предложение. Отклонённый обмен помечается `refusal=true`, не попадает в контекст
модели, извлечение памяти или исходный запрос после интервью.

Та же защита работает при создании задачи, пересмотре плана, планировании,
выполнении шага и проверке результата. Отказ сохраняется в истории, но не
меняет план, прогресс, состояние и версии задачи. Пауза и продолжение остаются
доступными. Старые базы автоматически получают признак отказа в сообщениях
без удаления прежней истории.

## API

- `GET /api/invariants` — текущие настройки и `revision`;
- `PUT /api/invariants` — заменить настройки, передав актуальную `revision`.

Поля: `emoji_enabled`, `min_emojis`, `uppercase_enabled`,
`sentence_limit_enabled`, `max_sentences`, `revision`. Сохранение устаревшей
редакции возвращает HTTP 409; невалидные типы и значения — HTTP 422.
Отказ в диалоге возвращается как обычный HTTP 200 с сообщением и признаком
`refusal`; отказ при создании задачи также возвращает HTTP 200 без новой задачи.
